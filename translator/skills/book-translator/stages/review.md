# Stage 3: independent review and bounded revision

Read the canonical format contract, source evidence, manuscript, glossary authorities, handoff, build verification and prior findings. Review may use an OpenAI or non-OpenAI model; stage 1/2 may not. Do not repair translation in the reviewer: return precise findings to the admitted translation stage. Any human input is optional except where source ambiguity or external authority actually requires it.

Review the entire book's semantic coverage, not just compilation or a few fluent excerpts. Compare every block and note to the original, including source-page transitions, OCR errors, omissions, duplication, captions, tables, cross references, mathematical punctuation and citations. Check protected span completeness as well as script-conserved declared spans: an undeclared name or variable can still have been translated incorrectly. Inspect code and comments byte-for-byte against the corrected source. Verify actual standards/locators rather than trusting plausible glossary citations.

Inspect actual PDF pages, not only TeX/logs: A5 and mirrored margins; outside printed-page marks at the correct content transition; no collisions or clipped marks; first term occurrence bold italic and numbered, repeated terms ordinary, appendix first translated page correct including note-first terms; image and multi-image geometry including text-side relationships; no group split/crop; footnote rule/bottom placement/continuation and half-page cap; agent preface at most two pages; optional human preface separate. Sparse or image-only pages are acceptable. The build report proves selected mechanical checks only.

Before reviewing, capture content_digest and pdf_sha256 from build/verification.json and independently confirm the PDF identity. Write reviews/round-N.json for the current job round with those exact reviewed identities, all eight named checks, exact PDF/source/manuscript locations, findings and inspection evidence. Pass means every check true, no findings, and a current build. A failed check or uncertainty that prevents faithful translation is changes_requested; do not hide it in a passing report. Submission compares the report identities to the current manuscript/PDF before recording a receipt; it must not stamp an old report with newer identities. If either artifact changes during review, inspect the changed artifact again and author a new current report, rather than merely changing the digest fields.

Submit via `review`. On changes_requested before the configured cap, route the entire findings set back to stage 2. At the default third failed translation/review pair, state becomes exhausted and no output.pdf is released. Do not add uncounted retries or expand max_rounds without explicit user choice. On pass, `accept` rechecks inputs/build/report before copying output.pdf. Record remaining nonblocking user-facing caveats truthfully; a report is not proof of model compliance, professional certification or measured workflow effectiveness.
