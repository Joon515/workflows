## Explicit startup activation

Copy the entire translator/ package into the target project's .agents/translator/ or .omp/translator/. Review an existing destination before replacing anything. Start a new OMP session from that project with BOTH the plugin directory and hook extension explicitly selected:

```sh
omp --plugin-dir .agents/translator -e .agents/translator/hooks/pre/translator.ts
# Or the other supported copy location:
omp --plugin-dir .omp/translator -e .omp/translator/hooks/pre/translator.ts
```

Use interactive `/skill:book-translator` with the actual task, or explicitly read the registered skill in that activated session. `--skills` filters discovered names; it is not a path loader. There is no singular --skill flag. No global settings edit, global extension install, repository-root instruction file or research checkout is required.

The plugin manifest discovers the skill; the explicit -e loads this package's native orchestration hook. Merely copying an arbitrary child directory, registering the skill or discovering files does not prove hook activation. Enabling/copying the hook after a session starts or hot-reloading alone is not sufficient: restart with the explicit startup invocation. Do not claim positional /skill expansion, a utility skill-list result or hook factory registration alone proves a native child execution.

Before source-bearing work, require all four package agents—book-source, book-terminology, book-translation and book-review—and both book_translator_prepare and book_translator_finish tools in the actual started session. Diagnose a missing hook/agent/tool rather than reverting to another launcher. [verify_install.py](../scripts/verify_install.py) checks portable activation without a model prompt; its execution results belong in verification.md. Registration checks do not prove authenticated inference, endpoint availability, a finalized native task or translation quality.

## Explicit selection and parent-local routing

The mandatory per-workflow ask policy and commands are in [operation.md](operation.md). The user chooses exact provider/model identities for all four roles; one model may serve all four. No vendor ban, automatic inheritance or unauthorized fallback exists. Explicit reuse of current configuration resolves and records exact identities. A missing or ambiguous choice blocks source work and dispatch; it is not authority to use parent/task/default settings.

Skill frontmatter does not select a model, and ordinary native task items have no model argument. The hook routes only the four named book agents through book_source, book_terminology, book_translation and book_review custom model roles on the current parent's runtime SettingsManager. These overrides remain local to that parent session until overwritten; finish does not restore them. It does not replace the parent's active model, rewrite unrelated default/task/smol roles or persist project/user/global configuration. Preparation also clears only the four book-role retry.fallbackChains entries in the parent runtime overlay; unrelated/default/provider-wildcard chains and ordinary parent fallback flags remain unchanged. Empty fallback chains alone are not strict runtime prevention, so native child startup separately disables modelFallback and usageAwareFallback in its child-scoped retry overlay. Existing settings overlays, agent overrides and fallback behavior make preference alone insufficient; admission also checks actual selected, startup, final and observed-request identities and the native task result.

The workflow stays in the current native OMP registry/authentication environment, retaining its supported OAuth, custom-provider and keyless/local configurations. It neither constructs a private provider registry nor forwards credentials into a separate omp/RPC process. A registry entry, authentication availability and a successful model request remain separate facts. Do not expose tokens or assume any service is free or continuously available. If the exact choice is unavailable, stop and obtain a new explicit choice rather than substituting a model.

## Native task evidence and coordinator authority

The only admitted role path is prepare, exactly one native task with the returned opaque assignment marker and unchanged nonempty dispatch strings, then finish. Pass details.context as top-level native task context and details.solutionSpace as the item solutionSpace, alongside details.agent and unchanged details.assignment as item task. Both strings are required by the exercised native task schema; the assignment marker supplies neither. Do not reconstruct them or substitute empty strings. The marker authorizes correlation with that persisted request; it is not reusable approval. The matching child receives the immutable stage or bounded-unit assignment only after model/session checks. The hook records finalized assistants, actual provider identities, lifecycle and the settled task result; the controller checks request/evidence/artifact bindings. Recovered intermediate same-model errors are not terminal failure: admission still requires exact identities on every assistant/request, a usable successful final assistant and a successful settled native task. Aborts, persisted host/capture failures and any observed fallback remain failures even if a later terminal field looks successful.

Eval-based book-agent dispatch is intentionally rejected because it cannot supply this flow's required final native task-result evidence, not because OMP is incapable of eval-based delegation. An unprepared native task, missing marker, extra/failed child, fallback, identity mismatch or incomplete terminal result is not a successful role run. Do not turn such a failure into a coordinator-authored glossary/source/report or manually declare a receipt. Hook installation or a final task badge alone is insufficient.

All four roles use the same native bridge; there is no second model-authoring backend. Source, translation and review of more than eight original source pages require bounded units. Planning validates full stage readiness once and binds immutable readiness and packet hashes. A unit writes only its assigned result and new asset directory; its finish validates its own native execution, unchanged canonical inputs and planned context, then preserves durable work without advancing the global stage or review round. It does not recursively replay every ancestor trace for every sibling. Completed units are not global stage admission. Assembly requires the complete source-page union, complete physical PDF review-page union where applicable, unchanged source/assets and full native proof closure before publishing a canonical manuscript/report. No persistent or metadata-only proof cache replaces release verification.

The coordinator separately validates/seals source, submits the exact admitted review report and accepts only a current passing build/report. Source coverage is conserved against controller-recorded extraction lineage and original locators, never a draft manuscript count. Existing small whole-role work remains supported. Sealed-source correction requires a newly prepared source revision and explicit resealing; terminology revision retains its pretranslation boundary. Translation authoring is durably admitted before fallible compilation and has inference-free finalization bound to that proof. See operation.md for commands/recovery; format.md alone defines fields.

Bounded page inspection records bind model-declared coverage to exact image hashes and native authorship. They do not independently prove perception, proofreading, semantic completeness or absence of duplicate continuations. Read-only neighboring blocks and protected context support seam checks; actual source and final-PDF review must still inspect every assigned page and compare boundary content. Unsupported structural ownership changes remain pending for explicit replanning, not silently omitted or treated as approved.

## Limits and historical jobs

This is local routing and observed-evidence admission, not a malicious-agent/filesystem/network sandbox, a universal per-request gate or independent endpoint attestation. Hooks may fail, time out or be disabled; throwing from a provider hook is not by itself a guaranteed hard veto. A source-bearing child must match before receiving workflow context, and no successful receipt is admitted without complete matching evidence, but this does not make arbitrary shell/network activity impossible or prove a remote endpoint truthful. Do not claim a trusted egress adapter was installed.

Keep the coordinator's unrelated dynamic defaults and global configuration unchanged. Preserve durable requests, finalized evidence, trace hashes, source seals, authored proofs, receipts and report/build identities. Do not retrofit model authorship, rewrite historical verification, migrate active jobs or reset rounds merely because a new workflow asks for model choices. Missing historical native provenance cannot be fabricated from an old manuscript or a successful compile.
