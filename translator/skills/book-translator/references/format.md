# Durable book contract

This document is the canonical data contract. JSON is UTF-8. Asset paths are relative to the job directory, cannot escape it, and cannot be absolute. Generated artifacts are not authoritative source evidence. All IDs match `[A-Za-z][A-Za-z0-9_-]*`. Book version is exactly 2; job, terminology, review and extraction versions remain 1. Version-1 books require explicitly reviewed source reconstruction under this contract and a new source seal; there is no implicit upgrade or compatibility renderer. Preserve historic jobs and their receipts rather than modifying them to appear current.

## Job directory

- `job.json`: `{version:1, title:string, source_language:string, target_language:string, source_file:string, source_sha256:string, max_rounds:3, round:0, state:"initialized", models:{source:Model,terminology:Model,translation:Model,review:Model}, layout:{paper:"a5", outer_mm:8, inner_min_mm:20, top_mm:15, bottom_mm:15, source_mark_edge_mm:3}, history:[]}`. Model is `{provider:string,model:string}` with an exact admitted provider/model identity, not an implicit parent/task/default alias. Every new workflow requires explicit current-user choices covering all four roles; an exact current choice already supplied fulfills intake without asking again. Ask only for missing, unavailable or ambiguous choices. One model may serve multiple roles when explicitly selected; explicit configuration reuse resolves and records exact identities. OpenAI and non-OpenAI providers are allowed. Registry/authentication, including OAuth/custom/keyless support, are reused through the current native runtime only, without a private executor/registry or global settings changes.
- `extraction.json`: evidence only, not a ready manuscript; see the extraction contract below.
- `book-source.json`: reviewed complete source structure. In unit mode only the controller writes this aggregate after admitting all required units; imported draft pages remain pending until individually inspected/admitted. Initial sealing requires current aggregate native source provenance for the exact source snapshot, then the coordinator writes source.sha256 before terminology. Once sealed, downstream source fields are immutable. Explicit source revision admits reviewed corrections against the old sealed job without replacing its seal/state/round; the coordinator deliberately runs seal-source --reseal using matching complete revision provenance. Changed-source resealing invalidates downstream admission/build/review approval; unchanged resealing cannot reset the round cap.
- `book.json`: translated version-2 manuscript with the same immutable source fields as book-source.json. Only title, optional title_terms, target, note target, agent_preface, human_preface and the optional output-only image/group fit policy below may change. It is never silently synthesized from unreviewed OCR. Restoration metadata and its source crop remain sealed source evidence.
- `terms.json`: `{version:1, terms:[{id:string, number:positive_integer, source:string, target:string, authority:string, authority_locator:string, rationale:string, protected_ids:[string]}]}`. Numbers and IDs are unique; authority is a relevant standard, normative terminology source or explicit field-consensus evidence. If no standard exists, record the decision and uncertainty, not a fabricated standard. protected_ids identify unchanged names inside this term; target must contain their literal values. Terms used anywhere in the book require table entries; unused table entries are rejected. Authority, locator and rationale remain audit data, not printed glossary columns. The printed glossary has four Chinese-labeled columns: number, original term, translated term and first-use page. First use follows actual reading order, never a manually supplied index. Keep physical PDF locations separate from displayed body-relative folios; a genuine title/preface/frontmatter first use is identified as before the body with its physical PDF index, never relabeled as a body page.
- `handoff.md`: stage 1 genre/domain/style/register, authority hierarchy, ambiguous choices, protected names/variables, source-quality caveats and chapter assignments. It is written by the explicitly selected, admitted terminology model.
- `reviews/round-N.json`: `{version:1, round:N, content_digest:string, pdf_sha256:string, verdict:"pass"|"changes_requested", checks:{coverage:bool, terminology:bool, protected_content:bool, source_pages:bool, image_relations:bool, footnotes:bool, typography:bool, preface:bool}, findings:[{id:string, severity:"blocking"|"major"|"minor", location:string, detail:string}], evidence:[string]}`. content_digest and pdf_sha256 are lowercase SHA256 identities captured from the exact manuscript and PDF inspected by the reviewer, before authoring the report; submission rejects a mismatch instead of relabeling an old report as current. Passing requires every check true and no findings. Evidence identifies inspected PDF pages and extraction/manuscript locations. Submitted pairs are immutable; explicit changed-source resealing archives journal-owned pairs under reviews/archive/ without removing audit history or unrelated files. An unchanged reseal cannot reset the round cap. A record alone cannot prove a model followed the workflow.
- `build/`: generated TeX, PDF, layout evidence and compiler log. Exact-model stage provenance binds the admitted manuscript/content digest, including layout and image inputs; its original compiled-PDF identity is execution evidence, not an authorship requirement for later recompilation of identical content. Current build verification and the author-reviewed report separately bind the exact current PDF bytes. Recompilation may change PDF metadata without changing admitted content; it requires current PDF review, not a new translation round. `output.pdf` is copied only by the final acceptance command after current-input digest and successful review checks.
- `provenance/`: immutable book-domain role checkpoints, source/review bindings and complete translation-authoring/finalization records. Native task metadata describes actual operator-observed settlement; it is not independent authentication attestation. Native OMP retains task/session journals. Preserve legacy request/evidence/trace/receipt bytes unchanged as historical data. A complete translation-authoring proof is persisted before backend build with authoring_complete:true and completed:false; failed compilation does not require new inference while the proof and content remain valid, and only successful finalization advances one round.

## Native result metadata and book checkpoints

Role is source, terminology, translation or review; its native agent name is exactly book-<role>. Parent operation is [operation.md](operation.md); activation and native model configuration are [omp-contract.md](omp-contract.md). Native OMP owns execution, model/authentication, retry/fallback policy, settlement and journals. The translator records completed book data and its bound inputs, not a second execution/authentication protocol.

### Actual settled result metadata

The coordinator persists the ACTUAL flat settled native SingleResult object as UTF-8 JSON. checkpoint-unit JOB ROLE UNIT_ID --task-result PATH and checkpoint-role JOB ROLE --task-result PATH [--revise] consume that file. Do not pass the outer task batch envelope, worker prose or a synthetic result derived from the requested model. Required metadata is:

```text
{id:string, agent:string, exitCode:integer, resolvedModelIdentity:string,
 resolvedModelIsFallback?:boolean, error?:string, aborted?:boolean}
```

id is nonblank, agent equals book-<role>, exitCode is integer 0, and actual resolvedModelIdentity equals the job's exact configured provider/model selector. resolvedModelIsFallback must be absent or false; error or aborted completion is rejected. Other normal native SingleResult fields may be present. The compact saved task metadata is normalized to {id,agent,exitCode:0,resolvedModelIdentity,resolvedModelIsFallback:false}. Never change actual native identity to the requested identity or conceal fallback/failure. Native OMP's policy remains native and unchanged; a checkpoint's stricter book-choice match does not implement a retry engine.

These checks are descriptive native operator metadata/book progress, not independently proved engine authentication, provider-request capture, endpoint identity or model perception. No assistant-message/lifecycle capture, opaque run token or hidden preparation/finishing protocol is required. The explicit current-user choices in job.models are book intent only; standard OMP agent frontmatter or native agent-model overrides must bind dispatch before source-bearing work.

### Whole-role and translation records

Small eligible whole-role source/translation/review and whole terminology use checkpoint-role. --revise is allowed for source correction or eligible pretranslation terminology revision, not an uncounted translation/review retry. Common whole-role record fields are:

```text
{version:1,kind:"book-role-checkpoint",role:Role,stage:Role,completed:true,
 provider:string,model:string,selector:string,task:object,
 source_digest:null|string,source_file_sha256:string,revision:boolean,bindings:object}
```

Source/terminology/review records live at returned provenance/<role>-<UUID>.json paths. UUID is a file identity, not a dispatch token. bindings hold the unchanged relevant book prerequisites: source_seal_sha256 for sealed work; prior_receipt/prior_receipt_sha256 for terminology revision; terminology_receipt/terminology_receipt_sha256, terms_sha256 and handoff_sha256 for translation; exact build identity for review. Source adds source_document_sha256/source_snapshot_digest; terminology adds terms_sha256/handoff_sha256. Review adds round, content_digest, pdf_sha256, verification_sha256 and review_sha256.

Source checkpointing/assembly never seals automatically. seal-source requires complete current source bindings and records source_receipt/source_receipt_sha256 in seal history. --reseal requires explicit matching source revision; corrected source remains inconsistent with the old seal until deliberate resealing. Changed resealing invalidates downstream book/build/review approval; unchanged resealing cannot reset rounds.

Translation preserves complete-authoring proof with kind:"translation-content-authored", authoring_complete:true, completed:false, unchanged content_digest, source/context/base-state/base-round and terminology/handoff bindings. Aggregate work keeps execution:"units" and original member checkpoint hashes, not a fictitious single author. Successful fresh canonical build/finalization creates the completed translation record and advances exactly one round. Pending proof or a unit checkpoint is not a completed round or release authority.

Review submission requires the exact complete checkpointed report and current content/PDF/build identities. It records reviewer_receipt/reviewer_receipt_sha256 in the submitted-review record. Checkpointing/assembly does not submit or accept. Acceptance rechecks the current passing report and exact PDF; old bytes cannot be relabeled as a new review.

### Explicit historical book-data import

import-checkpoints JOB ROLE --plan PATH validates a legacy native-unit-plan and its receipt-bound completed results. It writes a sibling book-plan.json using unchanged legacy packets/results, writes domain checkpoints with historical_origin:{path:string,sha256:string}, and switches active.json to that domain plan. Historical origin references the original receipt bytes by path/hash, not an invented current native task. Original job/legacy plan/packet/result/receipt/evidence bytes remain unchanged. Failed, unreceipted or merely present results are not imported as completed; pending IDs stay pending. This command imports book data only and calls no model.

### Explicit unsealed-source model continuation

continue-source JOB --provider P --model M is a book-data transition, not a task launcher. It requires an active domain source plan at extracted state, round 0, unsealed and nonrevision; the new source model must differ. The current user must explicitly authorize changing ALL FOUR FUTURE role choices to that exact provider/model. Initial configure-model remains an intent record, not a way to mutate an active plan in place. Native OMP model binding, authentication, retries and task settlement stay outside this command.

The controller validates current stable inputs and complete checkpoints, snapshots the exact old/new job bytes and creates a new active source plan. It updates the canonical job's four future choices and active pointer only as this validated transition. The continuation plan keeps original packet paths/hashes and owned/context content. Completed unit specs keep the original checkpoint path and add carried_checkpoint:{path:string,sha256:string}; those original checkpoints, models, native task metadata and history are not rewritten. Pending units receive fresh result, assets_dir and checkpoint paths, preserving failed or partial drafts. Carrying a checkpoint does not promote an uncheckpointed result.

The new plan includes continuation:{plan:string,plan_sha256:string,previous_job:{path:string,sha256:string},job_snapshot:{path:string,sha256:string}}, binding the prior plan and exact old/new job snapshots. Carried content validates against its checkpoint's original plan/model and unchanged book inputs; newly completed units validate against the future selected model and new plan. Original plans, packets, results, assets, checkpoints and legacy receipts remain unchanged. All extraction, ownership, complete coverage, body-boundary, source-seal and round gates remain mandatory.

The command returns normal unit-status fields plus carried:[unit IDs], selector, models, previous_job and job_snapshot. Plan selected_model and aggregate provider/model/selector describe the current/future choice, not a claim that every carried unit used it; unit_checkpoints retain each original author's actual model/task/history through original path/hash references. No new native execution, authentication evidence or model call is created by continuation.
## Durable page-bounded unit contract

UnitRole is source, translation or review; terminology is not a unit role. More than eight original source pages requires units for each UnitRole. Eligible whole-role work with at most eight source pages keeps its existing direct canonical-output path. The controller is the single canonical merge owner in unit mode. A worker must complete its entire assigned unit, not a sampled subset or the whole long book, and write only its assigned result and permitted assets.

### Planning, packets and recovery

plan-units JOB ROLE --pages-per-unit N [--draft PATH] [--revise] creates a durable plan, unit-status JOB ROLE reports progress, checkpoint-unit JOB ROLE UNIT_ID --task-result PATH checkpoints one complete settled result, and assemble-units JOB ROLE performs aggregate assembly. N is an integer from 1 through 8. Internal max_context_pages is an integer from 0 through 4 (default 4), not a CLI tuning option. The controller supplies immutable stage-readiness bindings, not a worker-authored execution proof. Initial source planning requires extracted/unsealed state; source correction requires explicit --revise. Translation requires terminology_ready or changes_requested with cap remaining; review requires a translated round and unchanged current build.

Paths are job-relative. units/<role>/active.json is {plan:string,plan_sha256:string}. A new plan is units/<role>/<plan_id>/plan.json, with packets/<unit_id>.json, results/<unit_id>.json, checkpoints/<unit_id>.json and assets/<unit_id>/ below its directory. New plan kind is book-unit-plan and packet kind is book-unit-packet. IDs are returned by planning, not chosen by workers. Plans/packets/page evidence and checkpointed results remain immutable. Explicit historical imports may retain legacy packet kind and original packet/result paths without rewriting their bytes.

Planning returns {plan:string,plan_sha256:string,role:UnitRole,units:[string],pages:integer}. Status returns {role:UnitRole,plan:string,plan_sha256:string,revision:boolean,base_state:string,base_round:integer,pages:integer,admitted:[string],pending:[string],complete:boolean}. admitted means domain checkpoint presence, not independent semantic verification or whole-book approval; assembly revalidates members/coverage. Resume pending IDs from disk and do not redispatch completed checkpointed work.

The version-1 domain plan binds plan_id, role, job_path/job_sha256, base_state/base_round, revision, selected_model, source_file_sha256/source_digest, canonical baseline hashes, extraction_sha256, pages_per_unit/max_context_pages, ordered page_ids, page evidence, metadata_owner, draft details, current review build/PDF identities, readiness, review_artifacts and unit ownership/packet/result/assets/checkpoint paths. readiness is {source_digest:null|string,bindings:object}, a controller book-readiness snapshot. Review binds hashes or absence of reviews/round-N.json and reviews/round-N.receipt.json so workers cannot prewrite the canonical report/submission.

A complete block's logical source/authoring owner is the unit owning its first source page; notes follow the callout block. Source and translation have complete exact-once original-page ownership. Review physical overflow repeats a bounded logical source scope without changing authoring ownership; review source inspection uses set-complete coverage and physical PDF ownership is exact-once. Keep crossing blocks intact with bounded additional context. Incoming blocks/notes and their owners are read-only, outgoing crossings are declared, and protected declarations have one owner plus read-only shared copies. Context grants no extra write scope.

Each version-1 packet binds role, unit_id, plan_id, source_file_sha256, owned_pages/context_pages, owned_block_ids/owned_note_ids/owned_protected_ids/shared_protected_ids, page evidence, owned blocks/notes, protected declarations, metadata_owner, metadata, compact heading outline, warnings and draft_is_untrusted. Seam fields are context_blocks:[Block], context_block_owners:{block_id:unit_id}, outgoing_block_ids:[string], context_notes:[Note], context_note_owners:{note_id:unit_id} and context_protected:[Protected]. Incoming structures are complete read-only evidence, not summaries to re-author. The packet/result paths and hashes select the sole writable unit result/assets directory. Review packets additionally bind exact current round/content/PDF/verification and assigned physical pages.

Plan creation validates book prerequisites once. Unit checkpointing checks unchanged job/source/terms/handoff/build/packet inputs, planned readiness, actual settled native result metadata and that unit's completed book result; it does not replay provider transcripts or claim authentication. Full book closure remains required at assembly, source seal/reseal, translation build/finalize, review submission and acceptance. A snapshot or inspection declaration never substitutes for completed book coverage.
### Result envelopes and page inspections

Each result must match the planned unit_id and packet_sha256, with version 1 and the exact role-specific kind. No unsupported top-level authoring fields are accepted. Open every assigned page image and inspect all content; never fabricate inspection entries. The declarations and hashes bind claimed inspection coverage to exact source evidence and descriptive native result identity. They do not independently demonstrate image perception, proofreading, semantic non-duplication or linguistic quality. Required visual inspection of every owned source/PDF page is an obligation; actual demonstrated compliance must be reported separately and truthfully. Neither OCR/draft text, token presence, sampled pages, book checkpoints nor a task badge establishes visual or semantic completeness. Review must inspect seams; no per-block geometric-span annotation contract is introduced.

Source result:

```text
{version:1, kind:"source-unit-result", unit_id:string, packet_sha256:string,
 source_pages:[SourcePage], blocks:[Block], notes:[Note], protected:[Protected],
 inspection:[PageInspection], body_start?:string,
 metadata?:{title:string,main_body_start?:null|string}}
```

source_pages must cover exactly the owned original pages, keeping their original locators. A source block starts on an owned page and references only prepared owned/context pages. EVERY prepared outgoing_block_id must survive in the result with identical source_pages; removing or shortening the crossing block is not allowed even if the rest of the unit appears covered. New source IDs may cover owned pages only. Unsupported newly introduced or changed crossing structure fails without consuming the unit: retain authored work as pending and explicitly replan rather than truncate/omit it or steal another owner's content. Read-only context_blocks/context_notes/context_protected and shared/non-owned protected declarations cannot be independently rewritten; incoming blocks are not new output ownership. New block/note/protected IDs use the unit_id underscore namespace; new assets belong in assets_dir unless reusing an allowed packet source asset. Prepared source_assets hashes remain immutable at finish/assembly; extraction freshness is rechecked at prepare/finish/assembly. Only the designated metadata owner supplies metadata, and that owner must supply it. All source data follows the Book version-2 protection/restoration contract below; a unit result is not independently a whole Book or source seal.

Source body-start declarations are separate from title metadata ownership. Optional top-level body_start is a string naming a nonblank block owned and returned by that unit. Declare it only if the actual FIRST main-body content begins there, never merely because a later chapter/section begins in the unit. For fresh packets whose metadata.main_body_start is null, the designated metadata owner still supplies the title but may omit metadata.main_body_start or set it null; it must not guess a remote body boundary. Other units may supply body_start without authoring metadata. Assembly combines all non-null body_start declarations with metadata.main_body_start and requires exactly ONE unique existing nonblank block ID. No candidate or conflicting candidates blocks assembly; the controller never guesses the minimum page, first heading or an automatic default. Existing known-draft metadata and already-authored valid result paths remain unchanged.

Translation result:

```text
{version:1, kind:"translation-unit-result", unit_id:string, packet_sha256:string,
 blocks:[{id:string,target:[Inline],fit?:Fit}], notes:[{id:string,target:[Inline]}],
 inspection:[PageInspection],
 metadata?:{title:string,title_terms?:[TitleTerm],agent_preface:[Inline],human_preface:null|[Inline]}}
```

Return exactly the owned block/note IDs, not full mutable source objects. Only target arrays and allowed image/group fit may change. Protected/page/note/non-prose-image token order and multiplicity must survive; approved term tokens expand the term's protected components for conservation checks. Only the designated metadata owner authors title/title_terms and the one book-level agent/human preface; every other unit omits metadata. Fit, title annotations and preface arrays use the canonical Book contracts below.

PageInspection is `{page_id:string,image_sha256:string,findings:[],protected_checked:true}`, exactly once for each owned original page, with the packet image hash. Source inspections additionally require `regions:[{index:integer,classification:"prose"|"nonprose"|"mixed"|"blank",semantic_ids:[string]}]`, covering every declared native raster-region index exactly once. For each prose/mixed region, at least one declared semantic ID must identify text-bearing semantics on that actual inspected page: an owned output block with page_id in source_pages, or a read-only context block with that page association. A prose note's page association follows the source_pages of its owning callout block, including prepared read-only context notes. Merely citing an existing ID from an unrelated page is inadmissible. These are page-bound model declarations, not geometric regions or independent perception/proofreading evidence. An empty region list is valid only when the packet declares no raster regions. Unresolved source/translation inspection defects block admission; review findings remain top-level report findings.

Review result:

```text
{version:1, kind:"review-unit-result", unit_id:string, packet_sha256:string,
 inspection:[PageInspection], pdf_inspection:[{page:integer,evidence:string}],
 verdict:"pass"|"changes_requested", checks:ReviewChecks,
 findings:[ReviewFinding], evidence:[string]}
```

ReviewChecks and ReviewFinding have exactly the eight check names and finding fields defined for reviews/round-N.json above. Findings use the unit_id underscore namespace. Report every semantic/layout issue in top-level findings; the source-image inspection record's findings:[] is not permission to hide review findings. A unit verdict is pass exactly when all its checks are true and it has no findings. pdf_inspection must enumerate exactly the owned physical pdf_pages, each with nonblank truthful inspection evidence. Source inspection separately covers every owned original page; the packet binds the exact round/manuscript/PDF/verification identities, so results do not invent new identity fields.

Review PDF ownership is derived from current build block boundaries, note start/end/callout pages, agent-preface pages and glossary rows. Logical metadata scope includes preface/glossary and remaining physical pages, then automatic physical splitting bounds every resulting task. Each physical PDF page has exactly one inspection owner. Read-only context is bounded to immediate physical seams as specified below, not every page touched by the repeated block scope. Assembly requires complete original-source coverage and exact-once physical-PDF coverage, never sampling. Review workers do not mutate source, translation, terminology or the canonical whole-book report.

Review plans bound both source scope and actual physical output work. Each review spec owns at most eight physical pdf_pages. The first physical chunk for logical source unit uNNNN keeps that ID; further chunks use deterministic uNNNN_pdf002, uNNNN_pdf003 and so on. Every review spec records source_unit_id:uNNNN. Overflow tasks repeat the same original source scope (at most eight owned source pages and the same immutable blocks/notes) rather than expanding or truncating it. Their source-page inspection coverage may overlap; aggregate source coverage must equal the complete original page set. Physical PDF page ownership/inspection remains exact-once over the full inventory. context_pdf_pages contains at most the immediate predecessor of the first owned page and successor of the last (at most two valid non-owned pages), not an unbounded secondary page list. This split is automatic, with no new public knob, sampling or truncation.

The review source_unit_id string is exposed in BOTH each plan unit spec and its immutable packet. Always checkpoint by the actual returned unit_id (including overflow suffix), not by replacing it with source_unit_id. Source inspection may repeat across these tasks; its union must equal the exact original source-page set with no unknown pages. Physical PDF inspection remains exact-once. Source/translation unit ownership and result envelopes are unchanged.

### Unit checkpoints and aggregate authorship

A unit checkpoint is:

```text
{version:1,kind:"book-unit-checkpoint",role:UnitRole,stage:UnitRole,completed:true,
 provider:string,model:string,selector:string,
 plan:string,plan_sha256:string,unit_id:string,packet:string,packet_sha256:string,
 result:string,result_sha256:string,assets:{path:sha256},
 source_file_sha256:string,source_digest:null|string,
 base_state:string,base_round:integer,revision:boolean,
 task?:object,historical_origin?:{path:string,sha256:string}}
```

Exactly one of task (actual normalized native metadata above) or historical_origin (explicit validated legacy import) records origin. Checkpointing returns checkpoint_path and checkpoint_sha256. It changes no job history, whole-book state/round, canonical manuscript, seal, build or approval. Preserve authored work if checkpointing fails; failed book admission is not permission to forge native settlement metadata.

Assembly checks every member checkpoint, immutable packet/result/page evidence/source asset, extraction freshness and complete structural ownership before publishing the canonical merge. Hashes and inspection declarations do not independently prove perception, proofreading, linguistic quality or absence of duplicate meaning. The aggregate explicitly records units, not a fictitious single child:

```text
{version:1,kind:"unit-role-completed",execution:"units",role:UnitRole,
 stage:UnitRole,completed:true,provider:string,model:string,selector:string,
 plan:string,plan_sha256:string,unit_checkpoints:[{path:string,sha256:string}],
 base_state:string,base_round:integer,revision:boolean,
 source_file_sha256:string,source_digest:null|string,
 merged_document:string,merged_document_sha256:string,merged_document_digest:string}
```

Source adds source_document_sha256/source_snapshot_digest and publishes book-source.json; sealing is separate. Translation adds content_digest and publishes book.json, preserving execution:"units" and member hashes in complete-authoring/finalized records. Only successful complete canonical build/finalization consumes one global round. Review publishes reviews/round-N.json and adds round, review_sha256, content_digest, pdf_sha256 and verification_sha256. Aggregate checks are the conjunction of unit checks; findings/inspection evidence combine in plan order. Whole-book pass requires every check true and no findings. Assembly never submits the report or accepts output.

No aggregate invents one task ID, runtime version, provider capture or transcript to stand for all authors. Validate original plan/member book bindings, including after normal global history/state advancement. Source seal/reseal, exact review freshness, round cap and acceptance rules remain unchanged. Every checkpointed unit is necessary; none alone establishes complete book release.
## Book object

Required fields: `{version:2, title:string, main_body_start:string, source_pages:[SourcePage], protected:[Protected], blocks:[Block], notes:[Note], agent_preface:[Inline...], human_preface:null|[Inline...]}`. main_body_start identifies an existing nonblank block selected from verified source structure, not the first heading guessed by the renderer. Optional `title_terms:[{term:string,start:integer,end:integer}]` stores only semantic annotations into the single canonical title string, not duplicate wording.

Title term spans use Unicode codepoint offsets (start inclusive, end exclusive), known term IDs and exact source-or-target literal matches. They are nonempty, in bounds, ordered and nonoverlapping; repeated IDs in distinct spans are allowed. The admitted translator selects every genuine visible-title occurrence, including source aliases, without blind substring classification. Rendering preserves each literal displayed slice; it does not replace aliases with another translation. Title references count as terminology use and register before prefaces/body. Missing/empty annotations perform no inference; source-only documents must omit them or leave them empty. They are mutable translation metadata and do not inject defaults into or reseal existing source data.

Translated running folios start at 1 on main_body_start; all earlier pages have no printed folio. Internal physical PDF indices remain continuous for binding, geometry, source positions and note evidence. No blank parity pages are inserted: body folio 1 need not be a physical right page. On physical left/even pages, the folio is at the outer left and the current level-1 chapter at the inner right of the header. On physical right/odd pages, the current level-2 section is at the inner left and the folio at the outer right. A new chapter clears the old section. Headers are running metadata, not new terminology occurrences or note callouts. No translated folio appears in the footer. Original-source folio annotations remain separate margin locators at their source-content transitions.

SourcePage: `{id:string, locator:string, printed_label:null|string, label_verified:boolean, evidence:string}`. Locator is an extraction page ID, spine location or original image location; NOT an original printed page number. A missing printed number is null. A present label must be transcribed from source evidence and label_verified must be true before source sealing. Roman numbers, prefixes, repeated labels and unnumbered pages are valid. EPUB/MOBI page-list or OCR candidates require provenance review; invented pagination is prohibited. Markers retain their natural font when they fit; an overwide marker is measured and proportionally fitted to outer_mm minus source_mark_edge_mm without changing its exact text, compiled baseline or mirrored edge anchor. Very long labels still require visual legibility review.

Protected: `{id:string, kind:"math"|"variable"|"code"|"name", value:string}`. Math/variable values are reviewed LaTeX; code is literal including comments/whitespace; names are literal original spelling. Protected values must survive exactly. No executable TeX commands are permitted in math: input/include/write/read/openout/catcode/csname/special/directlua and similar commands are rejected. Compilation always disables shell escape. A source formula can instead be preserved as an image asset if reliable transcription is unavailable; never replace it with invented LaTeX.

Inline is exactly one of `{text:string}`, `{protected:string}`, `{term:string}`, `{note:string}`, `{page:string}`, or `{image:{asset:string,width_em:positive_number,height_em:positive_number,raise_em:number}}`. Inline images preserve source raster glyphs/formula fragments at their reading position; all three numeric values must be finite, positive raise moves upward, and dimensions/raise use the current font em (including heading and note fonts). Normalize original image dimensions and baseline offset against the neighboring source font, retain the complete original raster and aspect ratio, and never guess missing math. These assets share ordinary source-asset containment, raster and seal checks; no generated assets or aliases into build/output are source evidence. A page token marks the exact source-page boundary, including inside a paragraph. Source inline arrays cannot contain term tokens. Target inline arrays must preserve exact values, order and multiplicity of image tokens as well as protected, note and page tokens from source. Terms may contain protected name IDs: term expansion counts these IDs toward that invariant. Text translation is the agent's work; scripts cannot establish semantic equivalence or discover every hidden name/variable.

Block common fields: `{id:string, kind:string, source_pages:[string], source:[Inline...], target:[Inline...]}`. Every block must have nonempty source_pages and source evidence. Kinds:

- `heading`: additionally `level:1|2|3`; target rendered as a heading.
- `paragraph`: source and target inline arrays; ordinary first lines indent by 2 em, including after headings. Captions retain their separate layout role.
- `display_math`: additionally `protected_id:string`; references protected kind math; source/target arrays may be empty and the protected reference is immutable.
- `code`: additionally `protected_id:string`; references protected kind code; rendered verbatim, never translated.
- `image`: additionally `asset:string, width:positive_number, height:positive_number, source_em:positive_number, scale_evidence:string`; all geometry and source_em share one source coordinate unit. source_em is the reviewed normal surrounding source running-text/body font em, not an arbitrary smaller caption or diagram-label font; scale_evidence identifies that role and calibration provenance. Output dimensions are source dimensions divided by source_em, in output body-font em. Raster pixels/DPI or glyph bbox height alone are not a source-font measurement. Caption goes in source/target. Image is indivisible.
- `group`: additionally `relation:"row"|"column"|"text-left"|"text-right", images:[{asset:string,x:number,y:number,width:positive_number,height:positive_number}], canvas_width:positive_number, canvas_height:positive_number, source_em:positive_number, scale_evidence:string, text_fraction:number`. Coordinates originate at top left of the source crop, in the same unit as source_em. Preserve panel offsets, gaps and proportions by one uniform source-to-output-font scale. text_fraction is between 0.2 and 0.8 and applies only to side-text groups. For text-left/text-right, text is beside the complete image canvas; for row/column it is a caption. Image/group size starts at its natural source-body-font-relative dimensions, never at full column width. Move an intact block to the next page when only remaining space is insufficient. The optional reviewed fit policy below permits bounded uniform reduction when the whole eligible page or side column is insufficient. Never crop, split, distort, enlarge or silently shrink complete artwork.

Image/group output may include `fit:{scale:number,min_scale:number,legibility_evidence:string}`. Both numbers are finite and `0 < min_scale <= scale <= 1`; evidence is a nonblank English rationale identifying the inspected labels, details and compiled output. Omit fit in book-source.json. Absent fit means scale 1. Apply one scale to the complete canvas, every panel size and offset; keep captions, side text and surrounding body font unchanged. Original source dimensions, source_em and scale_evidence remain sealed. Fit is mutable output metadata, but participates in content/provenance and current-PDF review identities; a changed fit invalidates stale approval.

Let natural output dimensions be `(w0,h0)=(source_width,source_height)/source_em * output_body_em`. A coordinator may propose `s=min(1,W/w0,H/h0)`, where W and H are the eligible graphic area after caption, side-text and footnote requirements, not the whole paper or merely remaining page space. This is a proposal, not automatic renderer fitting. Admit an explicit fit only after inspecting the actual output and choosing a justified min_scale; a numeric floor alone cannot prove legibility. An object still too large or unreadable fails with dimensions and requires a user-authorized constraint change. No implicit landscape, paper-size, crop or split fallback exists. Reliable reviewed formulas may use existing protected LaTeX; raster tables and diagrams remain complete images unless separately reconstructed and reviewed as a source change. This renderer does not implement a semantic table-reflow engine.
- `blank`: additionally `blank_evidence:string`; covers exactly one verified blank source page. source contains exactly that page token and no prose; the translated target conserves exactly the same token (a source-only target may remain empty). Keep this sealed source coverage/evidence, but omit the block, its source marker and any allocated output page. Do not insert explanatory blank-page prose. This default does not remove sparse pages containing real content.
- `list_item`: additionally `list_type:"ordered"|"unordered", list_level:integer from 0 through 8, label:string`. The immutable label is the original number/bullet marker; do not duplicate it in source/target prose. Items have 2-em initial indentation, additional indentation by nesting level, and hanging continuation lines aligned to item content. Preserve ordered labels and list depth rather than guessing a list from translated punctuation.

For image/group blocks, the consecutive leading page-token prefix denotes entry into the graphic content, not a boundary after its caption. Source and target leading prefixes must agree. The renderer anchors that prefix inside the indivisible graphic box so it follows page-fit movement; internal caption/side-text page transitions remain in their original relative content. Original token indices, IDs and multiplicities are retained. Graphic-start verification compares independent rendered panel/group geometry, not merely the same caption save-position.

Printed terminology source/target cells, explicitly annotated title aliases and protected literal text preserve exact apostrophe, quote, backtick and dash characters. Authority/decision audit data is not typeset. Ordinary prose keeps its normal typography.

Note: `{id:string, content_type:"prose"|"literal", source:[Inline...], target:[Inline...], source_evidence?:[{asset:string,source_page:string,description:string}], literal_reason?:string, restoration?:Restoration}`. Exactly one body note reference per note. source_evidence is immutable, non-rendered source-image/association evidence; its contained readable assets participate in source/content hashes. For a raster-origin explanatory note, transcribe verified prose into source and translate it into target; keep its complete raster as source_evidence, not an untranslated footer substitute. The explicit restoration crop below is the narrow rendered-evidence exception. Prose notes require semantic ordinary source text and translated prose/term content. Complete unchanged prose is rejected when normalized primary source/target language tags differ; equivalent regional/script variants are not automatically rejected, and this guard is not language-quality proof. Literal notes require an explicit literal_reason and may preserve protected formulas/code/names, punctuation and genuine non-prose images, not ordinary explanatory prose disguised as literal content. Mixed-note formulas and code remain protected; never invent math. Notes allow immutable non-prose inline images, but no nested note/page tokens. Keep visually verified original marker/callout associations; if the marker is locked inside a table image, retain it and document one editorially relocated canonical callout. Notes render as splitting bottom footnotes with the existing same-page reference, separator and half-text-height cap.

Restoration: `{source_page:string,original_fragment:string,replacement:string,status:"confirmed"|"conjectural",evidence:string,damage_asset:string}` on prose notes only. It binds the editorial repair to a verified source page in its owning block and a readable original damaged crop. Source prose immediately before its sole callout must end with the declared replacement (ignoring trailing whitespace); translated body conserves the callout, not the original-language replacement wording. Source and target note prose both retain original_fragment exactly and add only a concise completion notice alongside the declared crop. Preserve uncertain visible characters and mark illegible portions without inventing an original reading. damage_asset identifies exactly one conserved inline image in each note language; it may also be the explicitly identified source_evidence asset. Other prose-note evidence cannot be repurposed as an untranslated output image. All restoration fields, original excerpt, crop dimensions and crop bytes remain source-sealed internal verification data; they are not automatically typeset.

Default source preparation reconstructs recoverable damaged prose. The printed restoration note contains only a concise target-language completion notice, the verbatim original fragment and the supplied-source damaged crop; do not print a source locator, repeated replacement, confirmed/conjectural status, rationale or other commentary. Author this visible content in note.target; the renderer prints authored note.target, not automatic restoration-metadata disclosure. Keep source_page, replacement, status and rationale/evidence in immutable internal metadata for verification. Internal status confirmed means supported by inspected evidence; conjectural identifies an inference rather than claiming source certainty. If no defensible reading exists, preserve the uncertainty instead of fabricating a confident completion. Numerals, units, formula symbols and table values require independent verification before restoration; do not silently guess high-risk content. Semantic truth, status honesty and crop relevance still require source and PDF review, not schema validation alone.

Prefaces are inline arrays limited to text/protected/term tokens; nested note/page tokens are not allowed. agent_preface is required and nonempty for a translated book. human_preface is optional and is not counted toward the agent two-page limit. Agent preface discloses machine translation, terminology choices, source limitations and review status; it must not impersonate a human translator. First-use term formatting and first-output-page references follow actual reading order: explicitly annotated visible title, agent preface, optional human preface, then body headings/prose/captions and their notes. Use title_terms and inline term tokens for approved terminology at genuine occurrences; the appendix lists the first occurrence, not its own generated entry. This canonical rendering contract owns first-use behavior; historical handoff descriptions do not override it.

## Extraction contract

`{version:1, input:{path:string,sha256:string,format:string}, pages:[{id:string,locator:string,width:number,height:number,image:null|string,text:string,spans:[{text:string,bbox:[number,number,number,number]}],printed_label_candidates:[{text:string,evidence:string}],ocr:{needed:bool,performed:bool,engine:null|string}}], warnings:[string]}`. Span evidence additionally retains font_size, font_name, origin, font_size_source, font_size_unit, zero-based block_index/line_index/span_index, line_bbox/line_direction/line_wmode where exposed. Native font sizes are finite positive PDF points and coordinates follow the rotated page geometry. Provenance values native_pdf and reflow_layout describe extraction origin, not original-print attestation. OCR/DjVu unavailable font/baseline calibration stays null; native/subset-prefixed GlyphLessFont also provides no trusted size/baseline calibration. Never infer source em from bbox height or raster DPI.

IDs use p0001 etc. Additional extraction evidence fields are allowed: page.assets for embedded image assets, page.image_regions for native image rectangles, and page.ocr.text/spans for OCR separate from native text. Text, spans and page images are evidence, not an automatically approved reading order or correct original page number. Fixed-layout pages retain full rendered source images even if selectable text exists; mixed pages must not skip image-only regions simply because a text layer exists. OCR output is retained separately from original text when both exist, with enough locator information for review. Reflowable EPUB/MOBI render pages are temporary extraction locators, never original page numbers. Embedded images and original archive/source remain available for source-structure reconstruction. OCR may be explicitly required for all pages; missing OCR dependencies fail with actionable errors rather than claiming completion. DRM and unsupported/corrupt inputs fail without circumvention.

Canonical extraction inventory is bound to the latest controller-recorded extracted event and exact extraction byte SHA, original input SHA, unique page IDs and unique locators. A real extracted job with missing/mismatched journaled extraction is rejected rather than trusted as new evidence. Source completion/sealing must cover the exact ordered original extraction locators. Eligible small whole-role source authoring may rename source page IDs when uniqueness and exact ordered locators are preserved; unit mode still conserves its prepared owned page IDs/locators. These are inventory/identity checks, not independent visual perception or proofreading proof.

## Python module interfaces

All modules live beside `scripts/translator.py`. They use exceptions with actionable English messages and do not print successful completion on failure.

- `extract.py`: `doctor() -> dict`, `extract(source:Path, job_dir:Path, ocr:str="auto", language:str="eng", dpi:int=200) -> dict`. Writes extraction.json and evidence/assets, returns extraction object. OCR policies: auto, always, never. Never records skipped necessary OCR as performed. Native PyMuPDF EPUB/MOBI support is preferred; DjVu requires a real decoder.
- `core.py`: `load_json(path:Path) -> dict`, `save_json(path:Path, value:dict)`, `validate_document(kind:str, value:dict) -> None` for book/terms/job/review schema checks, `validate_book(job_dir:Path, translated:bool=True) -> dict` returns checked book or raises, `seal_source(job_dir:Path) -> str`, `content_digest(job_dir:Path) -> str`, `admit_model(provider:str, model:str) -> str` returns explicit provider/model selector or raises. Validation checks JSON schemas plus semantic invariants and source seal, assets and protected token preservation. Source validation ignores empty translation/preface targets. Terms schema validation permits unused entries until translated-book validation. No settings mutation.
  Canonical extraction helpers are `extraction_inventory(job) -> dict|None` (load/validate the journal-bound complete inventory) and `extraction_identity(job) -> str|None` (stream and validate its recorded byte SHA without per-unit full JSON decoding). A hash-bound plan may reuse the admitted inventory with exact identity checks; missing journaled extraction is not a fallback path. Absence of both extraction and its event preserves the low-level no-extraction case.
- `render.py`: `render(job_dir:Path) -> Path` writes build/book.tex using validated version-2 data; `build(job_dir:Path) -> Path` runs XeLaTeX via latexmk or repeated xelatex, emits build/verification.json bound to content_digest and returns build/book.pdf only after every mandatory gate passes. The eleven checks are compiler, pdf_geometry, preface, source_boundaries, image_relations, inline_images, footnotes, references, overflow, pagination and typography. Physical PDF locations and displayed page references are distinct evidence. Successful compilation or a subset of checks is not enough. Does not mark semantic approval or copy output.pdf.
- `translator.py`: domain CLI/controller owns book state, configure-model intent records, checkpoint-unit/checkpoint-role/import-checkpoints, single-owner assembly, source/review transitions and translation finalization. It does not own model execution/authentication/retries/native journals. Source/translation/review with more than eight source pages require units. Unit checkpointing changes no whole-book state/round; complete aggregate assembly/build applies global transitions. Public CLI commands above are the operational contract; modules remain importable from a copied package.
- `units.py`: domain unit planning, immutable packets, completed-result/asset/input validation, checkpoint storage, complete coverage, aggregate validation and canonical assembly. The controller supplies stage-readiness bindings and performs global transitions. Native execution/authentication/settlement is outside this module; worker metadata is not independently attested.

## Authority and failure boundaries

Schema validation establishes syntax and selected invariants, not accurate translation, OCR, standards compliance or truthful review. Source seals and book checkpoints guard accidental/stale transitions, not a malicious agent with filesystem access. LaTeX is a program interpreter: source data is untrusted, prose is escaped, assets/math are constrained and shell escape disabled. Use an authorized work directory without secrets and appropriate OS isolation for hostile parsers. Native OMP owns task execution/authentication/retries/journals; the book controller checks completed domain artifacts and descriptive native result metadata only. No engine authentication, provider implementation, visual perception, linguistic quality or trusted network egress is independently attested.
